# روند انجام و تحویل تغییر

## شروع

1. `git status --short` و diff را بررسی کنید؛ تغییرهای کاربر را حفظ کنید.
2. از [نقشهٔ docs](../README.md) راهنمای قابلیت را پیدا کنید.
3. route را تا Controller، service/repository، View و asset دنبال کنید؛ [راهنمای معماری](../architecture/overview.md) و [جدول routeها](../architecture/routing.md) نقطهٔ ورودند.
4. برای UI مالک واقعی فایل را در `tools/ui-owners.json` پیدا کنید.

## پیاده‌سازی و بازبینی

- مرجع داده را مشخص کنید: SQL/API، session، state موقت مرورگر یا دادهٔ نمونه.
- تغییر را در owner جاری انجام دهید؛ renderer یا قرارداد موازی ایجاد نکنید.
- UI را در state خالی، بارگذاری، خطا و موفقیت و اندازه‌های متناسب مرور کنید؛ RTL و دسترس‌پذیری را نگه دارید.
- سند همان حوزه را با قرارداد و محدودیت جاری به‌روز کنید.
- فقط فرمان‌های متناسب را اجرا و نتیجهٔ دقیق را ثبت کنید. راهنمای فرمان‌ها در [کیفیت](quality.md) است.

## تحویل

گزارش شامل مسیرهای تغییرکرده، منبع داده، بررسی‌های اجراشده و نتیجه، و محدودیت‌های باقیمانده باشد. پیش از تحویل `git diff --check` را اجرا کنید. برای هر تغییر مستندات، `node docs/development/check-docs.mjs` نیز لازم است.

## اعتبارسنجی اجراشده

- `npm.cmd run check`: کنترل قرارداد UI، مالکیت، بودجهٔ CSS، ترتیب وابستگی و مستندات موفق بود.
- `npm.cmd test`: هر ۲۶ تست واحد موفق بود.
- `dotnet build Shop.sln -c Release --no-restore`: موفق، بدون هشدار و خطا.
- `dotnet run --no-build -c Release --project tests/Shop.Contracts`: رد صحیح ۲۴ کاتالوگ نامعتبر و تأیید هویت canonical و JSON امن.
- `npm.cmd run test:http` با `SHOP_TEST_DLL=Shop/bin/Release/net10.0/Shop.dll`: هر پنج تست موفق؛ شامل بررسی ۱۰۸ صفحه، ۸۸ stylesheet و ۳۷۷ تصویر محلی یکتا.
- `npm.cmd run test:browser:list`: ده سناریوی دسکتاپ/موبایل کشف شدند؛ این فرمان اجرای سناریوها نیست.
- کنترل مستقل منابع مستندشدهٔ ۲۲ View، ترتیب ۴۹ asset سراسری، وجود مسیرهای inline کد، لینک‌های عنوان و توازن code fenceها انجام شد.
- `node docs/development/check-docs.mjs` و `git diff --check`: پس از اصلاحات اجرا شدند.

ساخت Debug اولیه به‌دلیل قفل فایل‌های برنامهٔ در حال اجرا شکست خورد. ساخت Release خروجی مستقل داشت و برای قراردادها و HTTP استفاده شد؛ سایت پورت ۵۱۰۰ متوقف نشد. مسیر تکرار این بررسی در [راه‌اندازی](setup.md) آمده است.

## بررسی مرورگر و اندازه‌های فایل

در Chrome روی localhost و عرض ۱۹۲۰px، عنوان، landmark اصلی و سرریز افقی صفحه در خانه، جستجوی دسته، محصول، سبد، تسویه، مقایسه، علاقه‌مندی، چهار مسیر پروفایل، مجله/مقاله، برندها/رونیکس، درباره، تماس، FAQ، ارسال، ضمانت، پیگیری و سه صفحهٔ قوانین بررسی شد. در این حالت‌ها سرریز افقی کل صفحه مشاهده نشد؛ این اندازه‌گیری تضمین نبود بریدگی در همهٔ اجزای داخلی نیست.

در محصول، انتخاب تصویر دوم، تغییر `aria-pressed`، بستن گالری و پیمایش «مشاهدهٔ همهٔ ویژگی‌ها» بررسی شد. پس از پایان پیمایش، مقصد مشخصات حدود ۲۶۴px از بالای viewport قرار گرفت؛ ارتفاع تب‌ها ۷۲px و بالای آن‌ها ۱۷۲px بود. این اعداد مربوط به همان viewport هستند؛ قواعد responsive مقدارهای دیگر دارند.

اندازه‌گیری فایل‌های رسانه نشان داد ۳۰ تصویر اصلی ۱۲۵۴×۱۲۵۴، ۳۰ نسخهٔ کارت ۸۰۰×۸۰۰ و ۳۰ بندانگشتی ۲۵۶×۲۵۶ هستند. پوشهٔ اسلایدر موبایل شش فایل ۱۰۰۰×۶۴۰ مصرف‌شده در hero و چهار فایل قدیمی ۱۰۰۰×۷۵۰ دارد. این بررسی اندازهٔ فایل است، نه تأیید کیفیت بصری یا محتوای تصویر.

## مواردی که هنوز قابلیت کامل محسوب نمی‌شوند

### بررسی موبایل پس از ممیزی

در دور تکمیلی، viewport مرورگر روی ۳۶۰×۸۰۰ تنظیم شد. صفحهٔ خانه باز و از نظر بصری دیده شد: سربرگ فشرده، hero، معرفی، راهنمای انتخاب و شبکهٔ دسته‌ها در نخستین viewport نمایش داده شدند؛ اندازه‌گیری DOM برای همین صفحه `innerWidth=360` و `scrollWidth=350` گزارش کرد، پس overflow افقی سند دیده نشد. بخش محتوایی تقریباً ۱۰px باریک‌تر از viewport گزارش شد و این اختلاف نیازمند بررسی در مرورگر پایدار است.

تغییر viewport به ۳۲۰، ۳۹۰ و breakpointهای دیگر چند بار timeout شد؛ پس از آن navigation و خواندن DOM نیز timeout دادند. بنابراین صفحات دیگر در این نوبت موبایلی راستی‌آزمایی نشدند. reset viewport هم timeout داد و بازگشت اندازهٔ مرورگر به حالت قبلی تأیید نشد. نتیجهٔ قبلی دسکتاپ به‌عنوان بررسی موبایل محسوب نمی‌شود.

اختلاف‌های خود برنامه در [رودمپ](roadmap.md) و راهنمای مسئول ثبت شده‌اند: reset عمومی focus، اندازهٔ کوچک کنترل تعداد، جستجوی متنی لینک دسته‌های فوتر و تفاوت مسیر JSON-LD محصول با مسیر نمایشی. اصلاح متن راهنما به معنی رفع این موارد در برنامه نیست.

قواعد موبایل با CSS و markup تطبیق داده شدند؛ اجرای بصری تمامی breakpointها، screen reader، contrast، print، آزمون کامل مرورگر و سناریوهای حساب/سبد پر با ارسال فرم در این ممیزی اجرا نشدند. دادهٔ مرورگر کاربر برای ساخت حالت آزمایشی پاک یا بازنویسی نشد. دامنهٔ عمومی، رسانه‌های خارجی، CI روی GitHub، درگاه واقعی و backend عملیاتی نیز با موفقیت تست محلی تأیید نمی‌شوند.

## بازبینی نام‌گذاری و دسته‌بندی، ۲۸ اکتبر ۲۰۲۶

- ساختار MVC از نظر نام پوشه‌ها و کلاس‌ها یکدست است: Controllerها، Modelها و Viewهای متناظر با convention چارچوب در پوشه‌های PascalCase قرار دارند؛ نام JS/CSS عمدتاً lowercase-kebab-case است.
- یک استثنا پیدا شد: دادهٔ `brand-editorial.json` داخل `shop/js/store/` بود، با اینکه فقط به‌عنوان داده توسط `BrandsController` خوانده می‌شد. فایل به `wwwroot/content/data/` منتقل و ارجاع سرور و مستندات اصلاح شد.
- مالکیت `brand-profile`، `magazine-list` و `article-detail` در `tools/ui-owners.json` اضافه شد تا markup، داده/مدل، رفتار و stylesheet هر بخش در یک نگاشت قابل‌ردیابی باشند.
- `App_Data/account-demo.json` در محل خصوصی سرور باقی می‌ماند؛ انتقال آن به `wwwroot/content/data/` نادرست بود چون نباید فایل عمومی شود.
- `layout/style.css`، `layout/industrial-system.css` و `pages/pages.css` فایل‌های بزرگِ قواعد مشترک قالب‌اند و در جای فعلی بخشی از زنجیرهٔ بارگذاری هستند؛ جابه‌جایی یا خردکردن آن‌ها هدف این پاک‌سازی نیست. نام‌هایشان میراث قالب است و تغییر نام به‌تنهایی ارزشی ندارد. قاعدهٔ جدید باید در stylesheet مالک مؤلفه نوشته شود. این مرزبندی در [معماری](../architecture/overview.md#قرارداد-نامگذاری-و-دسته‌بندی) و [CSS](../frontend/styling.md) ثبت شد.
- پوشه‌های `bin/obj` و خروجی‌های اعتبارسنجی تودرتو تولیدی و نادیده‌گرفته‌شده‌اند؛ به‌عنوان سورس یا بخش قابل‌نام‌گذاری جابه‌جا نشدند.

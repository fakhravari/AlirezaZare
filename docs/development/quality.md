# کنترل کیفیت و قراردادهای پایدار

## فرمان‌های محلی

پیش‌نیاز: .NET SDK 10 و Node.js 24. از ریشهٔ مخزن اجرا کنید؛ در PowerShell با محدودیت اجرای npm.ps1 از `npm.cmd` استفاده کنید.

```powershell
npm ci --ignore-scripts --no-fund --no-audit
npm run check
npm test
dotnet build Shop.sln
dotnet run --no-build --project tests/Shop.Contracts
npm run test:http
git diff --check
```

مسیر DLL تست HTTP با `SHOP_TEST_DLL` قابل تعیین است؛ نمونهٔ خروجی Release برای پرهیز از قفل فایل اجرای محلی در [راه‌اندازی](setup.md) آمده است.

`test:http` باید پس از build اجرا شود؛ DLL ساخته‌شده را روی پورت آزاد با محیط Development اجرا و پس از بررسی متوقف می‌کند. هم‌زمان با build روی همان DLL اجرا نکنید.

| کنترل | پوشش | محدودیت |
|---|---|---|
| `npm run check` | syntax همهٔ JSهای برنامه، parse CSS، مالکیت component، سقف !important، جایگاه توکن‌های عمومی تم در design-tokens.css، ترتیب dependency و ساختار/لینک docs | جای بررسی بصری را نمی‌گیرد |
| `npm test` | شناسه/URL/رسانهٔ قبل و بعد از انتقال، جابه‌جایی ترتیب کاتالوگ، immutable بودن، روابط، مسیر واقعی فایل‌ها، قیمت/موجودی سبد، migration و mount/event/renderer | منطق JS در محیط VM؛ فاقد layout مرورگر |
| `tests/Shop.Contracts` | خواندن واقعی CatalogSnapshot، رد داده‌های ناسازگار و JSON امن برای script | برنامهٔ contract با exit code، بدون وابستگی تست خارجی |
| `npm run test:http` | پاسخ مسیرهای اصلی، کاتالوگ مشترک صفحات، redirect canonical محصول و host، 404 کاربردی/noindex، noindex جستجو، metadata و H1 یکتای همهٔ URLهای sitemap، sitemap و تصویرهای صفحات و CSSهای مصرف‌شده | JS صفحه را اجرا نمی‌کند و redirect دامنهٔ اصلی را در DNS/میزبانی عمومی بررسی نمی‌کند؛ کنترل مسیر تصاویر در [رسانه](../media/images.md) توضیح داده شده است |
| `npm run test:browser` | خانه، جستجو و فیلتر طرح فروش در شبکهٔ یکپارچه، جزئیات و متعلقات متفاوت یک محصول در طرح‌های مختلف و رد متعلقهٔ غیرمجاز در quote، انتخاب طرح و بازیابی لینک منقضی محصول، گالری، سبد/تسویه و گروه‌بندی طرح‌ها، صفحه‌بندی علاقه‌مندی/کوپن، منوی دسکتاپ، sticky/scrollbar دیتیل مجله و تغییر چیدمان ستون کناری در breakpointها؛ پروژه‌های viewport دسکتاپ ۱۴۴۰×۱۰۰۰ و موبایل ۳۶۰×۸۰۰ | نیازمند مرورگر Playwright؛ اجرای واقعی جدا از فهرست‌کردن تست‌هاست؛ منوی دسکتاپ در پروژهٔ موبایل skip می‌شود |

تست‌های رفتاری مرورگر در [store.spec.mjs](../../tests/browser/store.spec.mjs)، [پنل‌های مهمان هدر](../../tests/browser/header-guest-panels.spec.mjs)، [پنجره‌های حساب](../../tests/browser/account-dialogs.spec.mjs)، [پنجره‌های فروشگاه و مجله](../../tests/browser/store-dialogs.spec.mjs)، [تعامل صفحات محتوا](../../tests/browser/content-interactions.spec.mjs) و [عرض صفحه‌های اصلی](../../tests/browser/page-layouts.spec.mjs) و تنظیمات در [playwright.config.mjs](../../playwright.config.mjs) هستند. تست پنل هدر بازبودن، تعامل‌ها و هدف لمسی ۴۴px کنترل تعداد/حذف سبد را در عرض‌های ۳۲۰، ۳۹۰، ۷۶۸ و ۹۹۱px بررسی می‌کند. آزمون پنجره‌ها در پروژهٔ موبایل از اندازهٔ ۳۲۰×۶۴۰ استفاده می‌کند و قرارگیری در viewport، نبود سرریز افقی و بسته‌شدن یا لغو را بررسی می‌کند؛ دادهٔ حساب در مرورگر آزمایشی جداگانه ذخیره می‌شود. آزمون عرض صفحه ۲۶ مسیر را در ۳۲۰، ۳۹۰، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ پیکسل از نظر پاسخ و سرریز افقی سند بررسی می‌کند؛ جایگزین بازبینی بصری محتوای داخلی نیست. `npm run test:browser:list` فقط کشف و اعتبار تنظیمات تست را بررسی می‌کند؛ موفقیت آن به معنی اجرای مرورگر نیست. در محیط توسعهٔ عادی پس از نصب مرورگر آزمایشی با `npx playwright install chromium` می‌توان تست‌ها را اجرا کرد. اگر محیط عامل، ابزار مرورگر مشخصی الزام کرده، از همان ابزار برای بررسی محلی استفاده کنید و این فرمان را مسیر دورزدن محدودیت اتصال قرار ندهید.

## مالکیت و جلوگیری از برگشت بدهی

شمار فعلی `!important` برابر ۲٬۵۸۸ در ۳۱ فایل است؛ اعداد پایین این بخش وضعیت هر مرحلهٔ پیشین را نشان می‌دهند. نقطهٔ ادامه در [دفترچهٔ مالکیت UI](../frontend/ui-ownership-roadmap.md) ثبت شده است.

[ui-owners.json](../../tools/ui-owners.json) مالک‌ها را بر اساس پنج حوزهٔ اصلی گروه‌بندی می‌کند و markup/data/server/JS/CSS اجزا را ثبت می‌کند. [check-ui.mjs](../../tools/check-ui.mjs) مسیرهای مسئول، وجود مالک برای همهٔ فایل‌های CSS/JS برنامه، شناسهٔ یکتا بین گروه‌ها و ترتیب بارگذاری را کنترل می‌کند. قبل از ساخت override یا renderer، این نقشه را بخوانید.

[ui-legacy-budget.json](../../tools/ui-legacy-budget.json) امضای قواعد فعلی component در فایل‌های قدیمی و سقف !important هر CSS را ثبت می‌کند. قواعد قبلی می‌توانند حذف یا به مالک منتقل شوند؛ افزودن/تغییر override خارج مالک با check رد می‌شود. check اعلان عادی یا `!important` تکراری را وقتی همان property، مسیر selector و شرط‌های والد را دارد و اعلان بعدی آن را می‌پوشاند، خطا می‌گیرد؛ selectorهای تو‌در‌تو نیز در مسیر بررسی حساب می‌شوند. برای رفع خطا baseline را یک‌جا بازتولید نکنید؛ قانون را به مالک ببرید. اگر انتقال کنترل‌شده به تغییر سقف نیاز داشت، diff دقیق همان ورودی، علت انتقال و نتیجهٔ بررسی مصرف‌کننده‌ها را ثبت کنید. امضاها مستقل از CRLF/LF هستند تا Windows و Linux نتیجهٔ یکسان بدهند.

۶۸ قانون اختصاصی کارت از industrial-system.css به shared-product-card.css منتقل شده‌اند؛ قاعدهٔ نمایش آیکن دکمهٔ سبد نیز اکنون در همان مالک ثبت شده است. ۱۷۹ اعلان سایه‌افتاده حذف و check برای جلوگیری از برگشت آن‌ها تقویت شده است. در منوهای برند و مشترک ۴۰ اعلان تکراری از فایل‌های قدیمی حذف شده‌اند و حداقل ارتفاع پنل برند در quick-links-menu.css ثبت شده است. در industrial-system.css، style.css، mobile-pages.css و shared-mega-menu.css مجموعاً ۱۱۱ اعلان معمولیِ سایه‌افتاده به‌وسیلهٔ `!important` بعدی حذف شده‌اند؛ ۲۳ اعلان بی‌اثر در pages.css، یک اعلان هم‌مقدار در about.css و هفت اعلان هم‌مقدار در shared-product-card.css نیز پاک شده‌اند. در مجموع ۲۵ بلوک خالی در مراحل این پاک‌سازی حذف شده‌اند. سایر قواعد legacy هنوز وجود دارند؛ مهاجرت بیشتر باید مرحله‌ای و همراه بررسی بصری باشد. حذف کامل CSSهای قدیمی انجام نشده است.

پاک‌سازی ۲ نوامبر ۲۰۲۶، ۳۰ declaration دقیقاً تکراری از زنجیرهٔ ۳۰ stylesheet مشترک را حذف کرد و سه rule خالی به‌علاوهٔ یک @media خالی را جمع کرد. ترتیب بارگذاری ثابت ماند. چهار declaration تکراری در سه rule مالک‌دار به‌دلیل رد check-ui حفظ شدند و سقف baseline دست‌نخورده ماند. در پایان آن مرحله شمار `!important` برابر ۳٬۱۶۸ در ۳۶ فایل از ۵۱ CSS بود.

در ممیزی بعدی، ۳۶ قاعدهٔ دارای ۱۳۸ declaration که فقط به ۱۳ نام کلاس بدون ارجاع در منبع برنامه مربوط بودند، از هفت stylesheet حذف شدند. قواعد قدیمی بخش «محصولات ویژه» نیز با markup و renderer خانه تطبیق داده شدند؛ ۱۰۷ قاعده با ۲۹۷ declaration در سه stylesheet حذف شد و ۱۴ قاعدهٔ گروهیِ محافظت‌شدهٔ کارت محصول باقی ماندند. دو `@media` خالی نیز جمع شدند. در پایان آن مرحله شمار `!important` برابر ۲٬۸۲۸ در ۳۶ فایل از ۵۱ CSS بود.

در ممیزی ۳ نوامبر ۲۰۲۶، ۱۸۷ قاعده و ۶۱۹ declaration از خانواده‌های قدیمی وبلاگ/مجله و ۸۱ قاعده و ۳۲۷ declaration از کنترل‌های قدیمی سبد خرید حذف شدند؛ handlerها و صفحه‌بندی بلاگ قدیمی نیز از `page-content.js` برداشته شدند. در مرحلهٔ بعد ۷ قاعده و ۲۱ declaration چیدمان شعبه‌های بلااستفاده و ۲۵ قاعده و ۱۰۲ declaration مستقل برای طرح حساب، کارت تماس و روند خدمات حذف شدند؛ شاخه‌های مشترک با اجزای فعال حفظ شدند. سپس ۴۹ قاعده و ۱۷۲ declaration از ابزارهای legacy مقایسه، جست‌وجوی محصول و مچ‌سازی حذف شد؛ سه `!important` نیز از همین بلوک‌ها کنار رفت و چهار selector ترکیبیِ قالب حفظ شد. ۳۰ قاعده و ۹۶ declaration مستقل از ticker، فرم جست‌وجوی قدیمی، لینک دسته‌بندی موبایل، نشان قدیمی و کارت شعبه نیز پاک شدند. استایل‌های جاری `hn-cart-*` و قواعد قالب حفظ شدند. چند خانوادهٔ قدیمیِ مستقل دیگر در ویترین و ابزارک‌های استفاده‌نشده نیز پس از تطبیق با منبع پاک شدند. در ادامهٔ همین ممیزی، ۹۴ قاعده و ۳۴۷ declarationِ بی‌مصرف از عنوان قیمت قدیمی، پنل‌های نمای کلی حساب، مشخصات قدیمی جست‌وجو، نشان برند/راهنمای اندازه و ویترین حقوقی/مقاله حذف شدند؛ selectorهای ترکیبی و قواعد مالک‌دار باقی ماندند. در گام بعد، ۲۳ قاعده و ۹۱ declaration از داستانک‌های قدیمی، دستهٔ مرتبط محصول، خلاصهٔ کوپن حساب، تصویر جایگزین برند و نوار ناوبری جست‌وجوی قدیمی حذف شد و پنج شاخهٔ بی‌مصرف scrollbar نیز از selectorهای مشترک برداشته شد؛ یک `!important` هم کم شد. در بازبینی شاخه‌های ترکیبی نیز ۳۰ شاخهٔ قدیمیِ بدون مصرف از selectorها حذف شد. هفت شاخهٔ دیگر در امضاهای محافظت‌شدهٔ page-hero و کارت محصول را پس از رد کنترل مالکیت به حالت اصلی برگرداندم؛ تغییر آن‌ها مستلزم بازنگری جداگانهٔ مالکیت است. در گام بعد ۱۸ قاعده و ۷۳ declaration از فرادادهٔ breadcrumb قدیمی، footer مگامنوی قدیمی، metadata/action ویترین مرتبط مقاله، آدرس شعبه و سکشن recommendations حذف شد؛ همچنین ۶ شاخهٔ stores-mini و related-posts از selectorهای مشترک حذف شدند. امضای template و مالکیت جابه‌جا نشد. در ادامهٔ تطبیق مستقیم با View و renderer جاری، قواعد بلااستفادهٔ electrical-art/kicker/CTA/slide-index و submenu قدیمی، footer-logo/view-all/stores، mega-content قدیمی و resend-code بدون مصرف، و aliasهای finder/compare حذف شدند؛ همین‌طور دکمهٔ لغوِ بدون markup در ویرایش پروفایل، سبک قدیمی invoice-item، metaهای قدیمی کالای مشابه و وضعیت‌های variant قدیمی، wrapperهای related صفحات FAQ/ارسال/پیگیری/گارانتی، legal-note و آیکن‌های قدیمی شعبه/سرویس/تماس پاک شدند. renderer جاری پیش‌فاکتور و `.flow-related` باقی ماندند. امضای owner-locked از جمله گروه کارت محصول حفظ شد. شمار فعلی `!important` برابر ۲٬۶۴۶ در ۳۵ فایل از ۵۱ CSS است؛ rule یا at-rule خالی وجود ندارد. `tools/ui-legacy-budget.json`، مالکیت component و ترتیب بارگذاری تغییر نکرده‌اند. `npm run check` و `git diff --check` موفق‌اند. پاک‌سازی CSS legacy هنوز ادامه دارد؛ selectorهای runtime/template و routeهای مصرف‌کننده گام بعدی‌اند.

در ادامهٔ همان تطبیق ایستا، ۱۹ قاعده و ۶۸ declaration از استایل‌های بی‌مصرف مقاله، حالت خالی حساب، تصویرهای چندمحصولی سفارش، کد کوپن نمای کلی، نام برندهای قدیمی ویترین و تزئینات مدار حذف شدند. شاخه‌های `.breadcrumb-item` و `.page-link` نیز از selectorهای مشترک برداشته شدند و ruleهای فعال حفظ شدند؛ handler، markup و renderer تغییر نکردند.

در دور بعد، ۷ قاعدهٔ مستقل با ۲۷ declaration برای آمار سؤال قدیمی حساب، متن پیش‌نویس، نشان وضعیت ذخیره، پیوندهای موبایل قدیمی، مگامنوی داخلی و عنوان انتخاب ویژگی حذف شد؛ keyframe بلااستفادهٔ `pageMegaFade` نیز پاک شد.

در ادامه ۸ قاعده و ۱۹ declaration از نشان‌های اعتماد قدیمی، برند footer، دسته‌بندی فروش موبایل و ابزار اندازه‌گیری مچ دست حذف شدند. شاخه‌های `trust-badge` و `wrist-trigger` نیز از قواعد ترکیبی برداشته شدند؛ markup فعلی footer و ابزار تصویر تغییری نکردند.

سپس ۳ قاعده و ۹ declaration از نقشه و برچسب شعبهٔ قدیمی، و ۶ قاعده با ۱۸ declaration از آیکن هدر قدیمی، نشانگر carousel، ticker و شبکهٔ محصول بلااستفاده حذف شدند؛ keyframe `ticker` نیز مصرفی نداشت. کد اسلایدرهای فعال حفظ شد.

در ادامه، سکشن قدیمی `#recommendations` و `.recommend-box` در View یا renderer جاری مصرف‌کننده نداشتند؛ ۷ قاعدهٔ مستقل با ۲۸ declaration و ۱۰ `!important` و نیز ۶ شاخهٔ selector آن از CSS خانه و موبایل حذف شدند. پرس‌وجوی reveal متناظر هم از JS برداشته شد. پنج شاخهٔ گروهیِ `.recommend-box` که کنترل مالکیت کارت محصول از تغییرشان جلوگیری می‌کند، باقی ماندند؛ شاخهٔ گروهی `.recommend-head p` هم به همین دلیل حفظ شد. شمار همان مرحله ۲٬۶۱۴ `!important` در ۳۲ فایل از ۵۱ بود؛ شمار و سقف هر فایل در `tools/ui-legacy-budget.json` ثبت شده‌اند و `npm run check` آن‌ها را کنترل می‌کند. هیچ rule یا at-rule خالی وجود ندارد.

در تطبیق بعدی، rule شاخه‌ای `.article-next-step > a.article-consult` هم مصرف‌کننده‌ای در markup نداشت؛ لینک جاری مجله همان style عمومی `.article-next-step > a` را می‌گیرد، پس rule قدیمی با سه declaration حذف شد.

دو شاخهٔ بدون ارجاع `.category-filter` و `.catalogue-filter` از قاعدهٔ وضعیت صفحه‌بندی و alias `.empty-state-kicker` از selector عنوان حالت خالی حذف شدند. قاعدهٔ صفحه‌بندی و کلاس جاری `.compare-empty-kicker` باقی ماندند.

تلاش برای حذف شاخه‌های `.article-author strong` و `.store-contact` از گروه‌های تایپوگرافی با رد check-ui روبه‌رو شد؛ چون امضای قواعد محافظت‌شدهٔ کارت را تغییر می‌داد، هر دو شاخه حفظ شدند.

کلاس `.store-card` در markup جاری مصرف‌کننده نداشت؛ ۱۶ قاعدهٔ مستقل با ۸۴ declaration و دو `!important`، هفت شاخهٔ گروهیِ آزاد و ورودی reveal آن از JS حذف شدند. شاخه‌های هم‌نام در امضای قواعد کارت محصول به‌دلیل کنترل مالکیت باقی ماندند.


در تطبیق بیشتر با markup و renderer کارت، ۴ قاعده و ۵ declaration از کلاس قدیمی `search-product-body`، متن کم‌رنگ فیلتر که در markup فعلی نبود، و شبکهٔ پنج‌ستونی قدیمی بخش `#amazing` حذف شد؛ یک `!important` هم کم شد. کلاس زندهٔ `product-info` و شبکهٔ جاری خانه دست‌نخورده ماندند. شاخهٔ بدون مصرف `.table-light > * > *` از گروه قاعدهٔ جدول جدا شد؛ استایل `thead` حفظ شد.

سپس ۲۰ قاعده با ۷۳ declaration دیگر حذف شدند: wrapper و legend چندطرحیِ منسوخ، عنوان برند و heading قدیمی کارت جست‌وجو، کنترل‌های carousel توصیه‌های غیرفعال، aliasهای overlay ورود و پنل popover حساب، و wrapper/فلش/فیلتررنگ‌های rail قدیمی. هشت `!important` مربوط به carousel توصیه‌ها پاک شد. کلاس‌های کارت محصولی که در امضای owner-locked هستند، با وجود نبود مصرف در markup، طبق کنترل `check-ui` حفظ شدند.

در مرحلهٔ نخست کاهش اولویت‌های فعال، دو `!important` فونت عمومی از `industrial-system.css` حذف شد؛ selectorهای بدنه و heading از قواعد عادی مؤلفه‌ها مشخص‌ترند و markup/renderer مقدار inline فونت ندارد. شمار جاری ۲٬۶۴۴ اعلان در ۳۵ stylesheet است. سقف ثبت‌شدهٔ هر فایل در `tools/ui-legacy-budget.json` به شمار جاری دقیق شد؛ کنترل `check-ui` اکنون هر افزایش را رد می‌کند.

در بازبینی آنلاین placeholderهای صفحهٔ جستجو و پیگیری سفارش، `color: #5d6a73 !important` در قاعدهٔ پایهٔ `::placeholder` مقدار رنگ تعریف‌شده در فایل‌های مالک صفحه را می‌پوشاند. `!important` از قاعدهٔ پایه برداشته شد؛ رنگ محلی `var(--industrial-muted)` اکنون برنده است و opacity، اندازه و وزن فونت پایه حفظ شدند. یک قاعدهٔ caret خانه نیز از `industrial-system.css` به فایل مالک ناوبری هدر منتقل و بدون `!important` نگه داشته شد؛ selector آن از قاعدهٔ Bootstrap مشخص‌تر است. تست‌های مرورگر مقدار placeholder را در search/tracking و پنهان‌ماندن caret را در چهار عرض دسکتاپ بررسی می‌کنند. شمار جاری ۲٬۵۷۱ `!important` است.

دو `border-top-*-radius !important` که در همان rule با `border-radius !important` بعدی پوشانده می‌شدند از `quick-links-menu.css` حذف شدند. `check-ui` برای این الگوی shorthand/longhand و چند خانوادهٔ رایج دیگر هشدار می‌دهد؛ شمار جاری ۲٬۶۴۲ است.

چهار `!important` دیگر از قواعد `.article-checklist`، stroke صفر آیکن‌های غیرفعال و `scrollbar-gutter` سبد حذف شدند؛ selectorهای فعال cascade عادی را برنده می‌کنند. شمار جاری ۲٬۶۳۸ در ۳۵ stylesheet است.

ممیزی ترتیب ۳۰ stylesheet ثابت در `_Shop.cshtml` یک `min-height: 62px !important` تکراری را از `style.css` حذف کرد؛ قاعدهٔ همسان در فایل مالک مگامنو بعدتر بارگذاری می‌شود. کنترل `check-ui` این تکرارها را از این پس می‌گیرد. شمار به ۲٬۶۳۷ در ۳۵ stylesheet رسید.

در View جزئیات محصول، `color: #173b5d !important` در selector قیمت متعلقه داخل `pages.css` با همان مقدار در stylesheet دیرتر و مالک جزئیات تکرار می‌شد؛ اعلان قدیمی حذف شد و امضای قاعدهٔ محافظت‌شده به‌روز شد. شمار به ۲٬۶۳۶ در ۳۵ stylesheet رسید.

## CI

[quality.yml](../../.github/workflows/quality.yml) دو job دارد: قراردادها/build/HTTP و مرورگر دسکتاپ/موبایل. شکست browser گزارش HTML، trace و تصویر خطا را هفت روز نگه می‌دارد. CI پس از push یا pull request اجرا می‌شود؛ وجود فایل workflow به معنی اجرای موفق آن در GitHub نیست. قیمت، auth و پرداخت این تست‌ها دمو و در context جداگانهٔ آزمایشی‌اند.

پس از تغییر، فرمان‌های اجراشده، نتیجه و محدودیت بررسی را دقیق گزارش کنید. [ماتریس UI](../frontend/verification.md) مرجع بررسی بصری، RTL و دسترس‌پذیری است.

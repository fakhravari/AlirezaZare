# کنترل کیفیت و قراردادهای پروژه

از ریشهٔ مخزن اجرا کنید. ابتدا راه‌اندازی محیط را در [setup](setup.md) بخوانید و فقط آزمون متناسب با تغییر را اجرا کنید.

## بررسی‌های پایدار

| هدف | فرمان/مرجع |
|---|---|
| ساخت کل solution | `dotnet build Shop.sln` |
| قراردادهای UI و اتصال ownerها | `node tools/check-ui.mjs` |
| پیوندها و دسته‌بندی Markdown | `node docs/development/check-docs.mjs` |
| whitespace و patch | `git diff --check` |
| اسکریپت‌ها و کنترل‌های تعریف‌شدهٔ مخزن | `npm run check` (محتوا را در `package.json` بخوانید) |
| قرارداد صفحه‌بندی فهرست‌های مدیریتی | `npm test` |

آزمون‌های `tests/unit/` قرارداد صفحه‌بندی API و مصرف آن در رابط مدیریت را بررسی می‌کنند؛ برای این آزمون‌ها به دیتابیس یا نشست کاربری نیاز نیست. اجرای build جای بررسی رفتاری و مرور UI را نمی‌گیرد. برای کار UI، `tools/ui-owners.json` را بررسی و رفتار را در viewportهای مربوط مرور کنید.

پایگاه اصلی را برای تست نوشتنی به کار نبرید مگر درخواست صریح کاربر و برنامهٔ امن و بازگشت‌پذیر وجود داشته باشد. خروجی هر فرمان را دقیق گزارش کنید. خطاهای محیطی یا secretهای پیکربندی را در مستندات/لاگ کپی نکنید.

تاریخ این بازنویسی: ۱۴ نوامبر ۲۰۲۶. پوشش آزمون‌ها از فایل‌های حاضر در checkout استخراج می‌شود؛ این راهنما وجود یا موفقیت آزمونی را تضمین نمی‌کند.

# راه‌اندازی و اجرای محلی

این مخزن solution دات‌نت در `Shop.sln` و اسکریپت‌های کیفیت Node در `package.json` دارد. نسخهٔ هدف برنامه‌ها را از فایل csproj و نسخهٔ ابزارهای JS را از `package.json`/lockfile تعیین کنید؛ این راهنما نسخهٔ نصب‌شدهٔ دستگاه را تضمین نمی‌کند.

## ساخت

```powershell
dotnet restore Shop.sln --artifacts-path C:\AlirezaZare-build-artifacts\restore
dotnet build Shop.sln --artifacts-path C:\AlirezaZare-build-artifacts\build
```

اجرای فروشگاه محلی:

```powershell
dotnet run --project Shop/Shop.csproj --artifacts-path C:\AlirezaZare-build-artifacts\run
```

پروفایل اجرا، پورت و environment را از `Shop/Properties/launchSettings.json` بررسی کنید. پنل مستقل است و با پروژهٔ `Admin/Admin.csproj` اجرا می‌شود. هر دو به SQL Server و `Data/Data.csproj` وابسته‌اند؛ اتصال را از تنظیمات environment/User Secrets بگیرید و مقدار secret را در سند یا خروجی ترمینال ثبت نکنید. خروجی و intermediateهای .NET باید با `--artifacts-path` زیر `C:\AlirezaZare-build-artifacts\` باشند؛ در Visual Studio ساخت محلی را به این مسیر هدایت کنید و از مسیر پیش‌فرض `bin/obj` استفاده نکنید.

## حفظ نشست پس از انتشار

کوکی‌های Shop و Admin با ASP.NET Core Data Protection محافظت می‌شوند. اگر کلیدهای رمزنگاری با جایگزینی برنامه پاک شوند، در حساب کاربری سرویس ذخیره نشوند یا مسیر برنامه و در نتیجه شناسهٔ برنامه تغییر کند، نسخهٔ جدید نمی‌تواند نشست پیشین را بخواند. پیش از تغییر، محل واقعی key ring و شناسهٔ برنامه را در محیط میزبان بررسی و از کلیدهای موجود نسخهٔ پشتیبان امن تهیه کنید؛ علت خروج در یک سرور مشخص باید از تنظیمات و log همان سرور تأیید شود.

هر دو برنامه نام `my-app-{EnvironmentName}` را برای Data Protection استفاده می‌کنند. مسیر پیش‌فرض کلیدها `App_Data/keys` در ریشهٔ محتوای هر برنامه است؛ در اجرای محلی `Admin/App_Data/keys` و `Shop/App_Data/keys` و در سرور پوشهٔ متناظر داخل ریشهٔ برنامهٔ منتشرشده استفاده می‌شود. حساب اجرای برنامه باید به پوشه دسترسی خواندن و نوشتن داشته باشد. مسیر مطلق دیگری را می‌توان با `DataProtection__KeysPath` مشخص کرد. نام محیط و کلیدها باید بین انتشارها ثابت بمانند؛ نمونه‌های متعدد هر برنامه به مسیر مشترک نیاز دارند. نام یکسان همراه با key ring مشترک، دامنهٔ رمزنگاری دو برنامه را مشترک می‌کند؛ مسیرهای Shop و Admin باید جدا باشند.

پروفایل‌های پوشه‌ای `DeleteExistingFiles` را غیرفعال می‌کنند تا مقصد هنگام انتشار پاک نشود؛ سایر ابزارهای استقرار نیز باید `App_Data/keys` را حفظ کنند. مقصدهای فعلی Shop و Admin به‌ترتیب `C:\export_web\shop` و `C:\export_web\admin` هستند. بنا به درخواست، پوشه و فایل‌های کلید در Git قابل ثبت‌اند، اما از خروجی build/publish کنار گذاشته می‌شوند؛ در این تنظیم محافظت رمزنگاری‌شدهٔ کلیدها در حالت ذخیره صریحاً پیکربندی نشده است، بنابراین دسترسی مخزن، پوشه و نسخهٔ پشتیبان آن را محدود کنید.

پیش از تغییر مسیر، از key ring قبلی نسخهٔ پشتیبان امن تهیه کنید و در صورت یکسان‌بودن نام برنامه و محیط، کلیدهای پیشین هر برنامه را به پوشهٔ جدید خودش منتقل کنید. اگر کلیدها در دسترس نباشند یا نام برنامه تغییر کرده باشد، نشست‌های قبلی معتبر نمی‌مانند و رمز FTP قدیمی محافظت‌شده ممکن است قابل بازیابی نباشد؛ صرف انتقال کلید بدون شناسهٔ قبلی کافی نیست.

اعتبار کوکی فروشگاه ۳۰ روز و ادمین ۸ ساعت با تمدید لغزان است؛ کوکی فروشگاه و کوکی ادمین بدون انتخاب «مرا به خاطر بسپار» نشست مرورگر هستند. انقضا، خروج عمدی، تغییر رمز یا غیرفعال‌شدن حساب ادمین مستقل از انتشار همچنان نشست را خاتمه می‌دهد.

## بررسی‌های مستندات و UI

```powershell
npm ci
node docs/development/check-docs.mjs
node tools/check-ui.mjs
git diff --check
```

فهرست فرمان‌های کیفیت در [quality.md](quality.md) است. مسیرهای نمونهٔ صفحات را در [routing](../architecture/routing.md) ببینید و پیش از تست endpoint از تنظیم پایگاه محلی مطمئن شوید. هیچ فرمان مهاجرتی یا seed در راه‌اندازی عمومی اجرا نمی‌شود؛ migration را فقط برای پایگاه هدفی اجرا کنید که دسترسی‌اش را تعیین کرده‌اید.

## تشخیص خطا

- خطای DB: connection string محیط جاری و دسترسی SQL را بررسی کنید؛ کد 500 را با fallback دمو مخفی نکنید.
- پورت اشغال: پروفایل اجرا را بررسی یا پورت آزاد صریح انتخاب کنید.
- CSS/JS قدیمی: URL واقعی، `asp-append-version` و cache مرورگر را بررسی کنید.
- شکست npm check: ببینید کدام script شکست خورده؛ `npm run check` زنجیره‌ای است و شکست مرحلهٔ اول مراحل بعدی را اجرا نمی‌کند.

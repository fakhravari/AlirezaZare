# برنامهٔ مالکیت و تفکیک بخش‌های رابط کاربری

این سند مرجع پیشرفت کارهای چندمرحله‌ای برای روشن‌کردن مالک هر بخش UI و انتقال استایل‌های بزرگ و مستقل به فایل مسئول همان بخش است. با توقف یا شروع دوبارهٔ کار، از وضعیت و «گام بعدی» همین سند ادامه دهید.

## قانون پیگیری

- هر تغییر چندمرحله‌ای در مالکیت یا تفکیک UI باید در همین سند ثبت شود؛ برای هر موضوع یک بخش وضعیت داشته باشید، نه سند پیشرفت جداگانه.
- درصد را از چک‌لیست‌های انجام‌شده نسبت به کل گام‌های تعریف‌شده حساب کنید و پس از هر گام کد، درصد و نقطهٔ شروع بعدی را همین‌جا به‌روز کنید.
- پیش از جابه‌جایی، مالک markup و CSS/JS، مصرف‌کننده‌ها و ترتیب بارگذاری واقعی را بررسی کنید. قواعد عمومی قالب را صرفاً برای مرتب‌سازی منتقل نکنید؛ فقط بخش مستقل با مالک روشن جدا شود.
- پس از هر انتقال، فایل مالک و `tools/ui-owners.json` را هماهنگ کنید؛ بدهی `!important` را به‌عنوان baseline تازه اضافه نکنید. بررسی UI باید روی localhost و در اندازهٔ دسکتاپ و موبایل باشد.
- هنگام توقف، مورد نیمه‌تمام، محدودیت بررسی و مسیر دقیق شروع بعدی را ثبت کنید.

### گروه‌بندی مالک‌ها

مالک‌ها در `tools/ui-owners.json` زیر پنج گروه حوزه‌ای `home`، `store`، `account`، `content` و `shared` چیده شده‌اند. زیر‌بخش‌های واقعی زیر حوزهٔ خود نگهداری می‌شوند؛ برای هر route گروه top-level جدا ساخته نمی‌شود. `tools/check-ui.mjs` فایل‌های همهٔ گروه‌ها را اعتبارسنجی می‌کند.

### گام بعدی

این مرحله کامل است. برای تغییرات بعدی مالکیت UI، از ممیزی مالک component و مسیر load در `tools/ui-owners.json` شروع کنید و وضعیت کار تازه را همین‌جا ثبت کنید. قواعد عمومی قالب و ویترین دسته‌بندی مشترک را برای ساخت فایل اختصاصی بی‌دلیل تکثیر نکنید.

### بررسی‌های انجام‌شده تا این نقطه

- `npm.cmd run check` موفق: مالکیت‌ها، بودجهٔ legacy و ترتیب منابع معتبرند.
- `node docs/development/check-docs.mjs` و `git diff --check` موفق.
- `dotnet build Shop.sln -c Release --no-restore` موفق، بدون warning و error.
- صفحهٔ خانه روی localhost در عرض‌های ۱۴۴۰ و ۳۹۰ بررسی شد؛ هر سه stylesheet اختصاصی مجموعه/برند/دیدگاه یک‌بار بارگذاری شدند، overflow صفحه در هر دو اندازه دیده نشد و خطای کنسول ثبت نشد. cloneهای داخلی اسلایدر Owl از viewport بیرون می‌روند اما روی عرض سند اثر ندارند.
- ساخت Release، قراردادهای C#، آزمون‌های JS و HTTP محلی پس از استخراج CSS و گروه‌بندی مالکیت اجرا شدند و موفق بودند؛ `npm run check` و کنترل مستندات نیز موفق‌اند.

### گام بعدی

این برنامهٔ چهارمرحله‌ای کامل است. ممیزی جداگانهٔ `!important` از ۲٬۶۴۶ مورد شروع شد: دو اعلان فونت عمومی، دو radius سایه‌افتاده، چهار اولویت بی‌نیاز در checklist، آیکن‌ها و اسکرول سبد و دو تکرار قطعی بین stylesheetهای هم‌بارگذاری حذف شدند. در مرور مالک‌محور، سه رنگ/زمینهٔ آیکن گروه مقایسه از `industrial-system.css` به `commerce.css` منتقل شدند؛ مقادیر محاسبه‌شده حفظ شدند و مالک `compare-page` تغییر نکرد. همچنین rule عمومی `.product-detail-sale-meta` از فایل سراسری حذف شد چون جزئیات آن در CSS مالک محصول تعریف شده است. ممیزی ترتیب stylesheetهای مشترک ۵۳ declaration تکراری را از `industrial-system.css` برداشت (دو مورد `!important`) و check-ui حالا بازنویسی declaration سراسری را در فایل دیرتر گزارش می‌کند. کنترل longhand/shorthand و کپی دقیق selector/شرط/مقدار نیز فعال است. بودجهٔ هر ۵۱ فایل با شمار واقعی برابر است تا افزایش تعداد رد شود. ۲٬۶۲۸ مورد در ۳۵ فایل مانده‌اند (حدود ۰٫۷٪ کاهش). گام بعدی بررسی قواعد high-impact در `industrial-system.css` با cascade و owner صفحه‌های محلی در دسکتاپ/موبایل است.

### این دور: ممیزی زنجیرهٔ cascade مشترک — ۱۰۰٪ (۴ از ۴ گام)

| گام | وضعیت | نتیجه |
|---|---|---|
| تطبیق قواعد با ترتیب واقعی `_Shop.cshtml` | انجام شد | ۳۰ stylesheet مشترک با selector و شرط یکسان بررسی شدند. |
| حذف declarationهای بازنویسی‌شده | انجام شد | ۵۳ declaration از `industrial-system.css` حذف شد؛ ۲ مورد آن `!important` بود. مقدار برنده در فایل دیرتر حفظ شد. |
| محدودکردن استایل مؤلفه‌ها به owner | انجام شد | رنگ آیکن مقایسه در CSS مالک مقایسه باقی ماند و قاعدهٔ عمومی metadata قیمت جزئیات محصول حذف شد؛ مالک جدید یا فایل موازی ساخته نشد. |
| اعتبارسنجی و مستندات | انجام شد | خانه، منوی طرح، گالری و دیتیل در دسکتاپ و موبایل ۹ تست موفق و یک skip مورد انتظار داشتند؛ `npm run check` و `git diff --check` نیز موفق شدند. |

این دور کامل است، اما پاک‌سازی کلی `!important` تمام نشده: شمار واقعی ۲٬۶۲۰ در ۳۵ فایل از ۵۱ باقی مانده است. پس از حذف سه مورد از حالت disabled دکمه در `product-detail-pricing.css` و چهار مورد از مالک `checkout.css`، اولویت text-align توضیح footer نیز حذف شد؛ selector دقیق footer از قاعدهٔ دیرتر و عمومی‌تر برنده می‌شود. بررسی محلی `/checkout` نشان داد selector یادداشت پیش‌فاکتور باید از قاعدهٔ دیرتر `industrial-system.css` مشخص‌تر باشد؛ selector مالک به `.invoice-page .cart-summary .invoice-demo-note` محدود شد و فونت ۱۳px را در عرض‌های ۱۹۲۰ و ۳۹۰px حفظ می‌کند. margin پیام نبود آدرس در همان مالک نیز بدون اولویت عمومی حفظ می‌شود. در موبایل overflow افقی دیده نشد. پنجرهٔ ورود روی محتوا بود و سبد خالی بود، بنابراین وضعیت روش پرداخت و نمای کامل صفحه دیداری بررسی نشد. مرحلهٔ بعد: ممیزی cascade و owner برای selectorهای پرتکرار باقی‌مانده در `industrial-system.css` و سپس فایل‌های پرتراکم دیگر؛ هر breakpoint فقط روی localhost بررسی شود.

# برنامهٔ مالکیت و تفکیک بخش‌های رابط کاربری

این سند مرجع پیشرفت کارهای چندمرحله‌ای برای روشن‌کردن مالک هر بخش UI و انتقال استایل‌های بزرگ و مستقل به فایل مسئول همان بخش است. با توقف یا شروع دوبارهٔ کار، از وضعیت و «گام بعدی» همین سند ادامه دهید.

## قانون پیگیری

- هر تغییر چندمرحله‌ای در مالکیت یا تفکیک UI باید در همین سند ثبت شود؛ برای هر موضوع یک بخش وضعیت داشته باشید، نه سند پیشرفت جداگانه.
- درصد را از چک‌لیست‌های انجام‌شده نسبت به کل گام‌های تعریف‌شده حساب کنید و پس از هر گام کد، درصد و نقطهٔ شروع بعدی را همین‌جا به‌روز کنید.
- پیش از جابه‌جایی، مالک markup و CSS/JS، مصرف‌کننده‌ها و ترتیب بارگذاری واقعی را بررسی کنید. قواعد عمومی قالب را صرفاً برای مرتب‌سازی منتقل نکنید؛ فقط بخش مستقل با مالک روشن جدا شود.
- پس از هر انتقال، فایل مالک و `tools/ui-owners.json` را هماهنگ کنید؛ بدهی `!important` را به‌عنوان baseline تازه اضافه نکنید. بررسی UI باید روی localhost و در اندازهٔ دسکتاپ و موبایل باشد.
- هنگام توقف، مورد نیمه‌تمام، محدودیت بررسی و مسیر دقیق شروع بعدی را ثبت کنید.

### گروه‌بندی مالک‌ها

مالک‌ها در `tools/ui-owners.json` زیر پنج گروه حوزه‌ای `home`، `store`، `account`، `content` و `shared` چیده شده‌اند. زیر‌بخش‌های واقعی زیر حوزهٔ خود نگهداری می‌شوند؛ برای هر route گروه top-level جدا ساخته نمی‌شود. `tools/check-ui.mjs` فایل‌های همهٔ گروه‌ها را اعتبارسنجی می‌کند.

### گام بعدی

این مرحله کامل است. برای تغییرات بعدی مالکیت UI، از ممیزی مالک component و مسیر load در `tools/ui-owners.json` شروع کنید و وضعیت کار تازه را همین‌جا ثبت کنید. قواعد عمومی قالب و ویترین دسته‌بندی مشترک را برای ساخت فایل اختصاصی بی‌دلیل تکثیر نکنید.

### بررسی‌های انجام‌شده تا این نقطه

- `npm.cmd run check` موفق: مالکیت‌ها، بودجهٔ legacy و ترتیب منابع معتبرند.
- `node docs/development/check-docs.mjs` و `git diff --check` موفق.
- `dotnet build Shop.sln -c Release --no-restore` موفق، بدون warning و error.
- صفحهٔ خانه روی localhost در عرض‌های ۱۴۴۰ و ۳۹۰ بررسی شد؛ هر سه stylesheet اختصاصی مجموعه/برند/دیدگاه یک‌بار بارگذاری شدند، overflow صفحه در هر دو اندازه دیده نشد و خطای کنسول ثبت نشد. cloneهای داخلی اسلایدر Owl از viewport بیرون می‌روند اما روی عرض سند اثر ندارند.
- ساخت Release، قراردادهای C#، آزمون‌های JS و HTTP محلی پس از استخراج CSS و گروه‌بندی مالکیت اجرا شدند و موفق بودند؛ `npm run check` و کنترل مستندات نیز موفق‌اند.

## پاک‌سازی اولویت‌های سایه‌افتاده در CSS مشترک

**پیشرفت این مرحله: ۱۰۰٪ — هر ۴ گام انجام شده‌اند.** این درصد فقط همین مرحله را پوشش می‌دهد؛ پاک‌سازی کل CSS قدیمی تمام نشده است.

| گام | وضعیت | نتیجه |
|---|---|---|
| تطبیق زنجیرهٔ بارگذاری مشترک و route با `_Shop.cshtml` | انجام شد | دو declaration تکراری/سایه‌افتاده در زنجیرهٔ واقعی صفحه حذف شد؛ قواعد مشترک قالب و ترتیب فایل‌ها ثابت ماند. |
| حذف اولویت‌های قطعاً سایه‌افتاده | انجام شد | چهار declaration سایه‌افتاده حذف شد؛ دو override قالب در `industrial-system.css` پس از رد checker حفظ شد. گروه مالک‌ها گسترش نیافت و template rules جابه‌جا نشد. |
| بررسی محلی اندازهٔ دسکتاپ و موبایل | انجام شد | خانه در ۱۴۴۰ و ۳۹۰px، مقاله در ۱۴۴۰ و ۳۹۰px، و منوی برند در دسکتاپ بررسی شد؛ overflow افقی و خطای کنسول نبود. |
| به‌روزرسانی راهنما و اجرای کنترل کیفیت | انجام شد | شمارندهٔ `!important` به ۳٬۱۷۰ رسید؛ `npm run check`، ۳۳ آزمون واحد و کنترل مستندات موفق بودند. آزمون مرورگر دسکتاپ/موبایل ۲۳ مورد موفق و یک منوی دسکتاپ را در موبایل طبق انتظار skip کرد. |

### گام بعدی

ممیزی ساختاری routeها یک مورد با مقدار متفاوت برای ارتفاع Hero در `page-hero-imagery.css` و یک مورد برای رنگ فعال آیکن در `mega-menu-unified.css` نشان می‌دهد؛ قواعد template در `industrial-system.css` فعلاً نگه داشته می‌شوند. موردهای با مقدار متفاوت باید با مرور بصری در خود مالک بررسی شوند. گروه مالک‌ها را بزرگ‌تر نکنید و قواعد قالب را جابه‌جا نکنید.

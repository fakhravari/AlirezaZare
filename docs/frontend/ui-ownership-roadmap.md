## آغاز بررسی

۱. `tools/ui-owners.json` را بخوانید؛ ۲. مسیر markup/CSS/JS واقعی را بررسی کنید؛ ۳. `node tools/check-ui.mjs` اجرا کنید؛ ۴. مرور بصری و نتیجه را ثبت کنید.

## کار فعال: Select2 سراسری برای فهرست‌های انتخاب

- **حوزه/owner:** `admin-panel/admin-shell` و لایهٔ مشترک فروشگاه؛ ownerها در `tools/ui-owners.json`.
- **وضعیت و درصد:** پیاده‌سازی سراسری کامل؛ بازبینی Admin کامل و Shop به‌علت خطای پایگاه‌دادهٔ محلی مسدود است (۹۰٪).
- **تغییرهای تکمیل‌شده و شاهد:** در Admin، انتخاب نقش در کاربران و فیلترهای انبار/طرح در viewport رومیزی و ۳۹۰×۸۴۴ بررسی شدند؛ Select2 فارسی/RTL و عرض کنترل‌ها درست بود، تغییر فیلتر انبار نتایج را محدود کرد و صفحه اسکرول افقی ناخواسته نداشت. selectهای فرم ایجاد/ویرایش محصول و فایل در modal نیز مقداردهی شده‌اند. راه‌اندازهای ایستا/پویا و اتصال dropdown به modal در کد بررسی شد.
- **فایل‌های باقی‌مانده:** مرور بصری Shop، به‌ویژه استان/شهر و selectهای modal.
- **گام بعدی دقیق:** پس از آماده‌شدن schema محلی Shop، مرور Shop در دسکتاپ و موبایل و ثبت نتیجه.
- **محدودیت/فرمان اجرا‌نشده:** اجرای محلی Shop با خطای SQL `Invalid object name 'Account.Coupon'` پاسخ ۵۰۰ می‌دهد؛ بنابراین تست بصری Shop ممکن نشد.

## کار فعال: یکدست‌سازی دکمه‌های عملیات جدول Admin

- **حوزه/owner:** `admin-panel/admin-shell`؛ قرارداد دکمه و renderer مشترک در `Admin/wwwroot/js/admin-ui.js` و ظاهر در `Admin/wwwroot/css/admin-ui.css`.
- **وضعیت و درصد:** بازبینی بصری نمایندهٔ Admin کامل (۱۰۰٪ برای renderer مشترک).
- **تغییرهای تکمیل‌شده و شاهد:** جدول کاربران، محصولات و موجودی انبار در دسکتاپ و موبایل بررسی شد. دکمه‌ها در هر ردیف ارتفاع یکسان ۳۶ پیکسل، آیکن، برچسب کوتاه و عنوان/نام دسترس‌پذیر دارند. در موبایل جدول داخل ظرف واکنش‌گرا پیمایش افقی دارد و عرض صفحه را نمی‌شکند؛ دکمه‌ها در همان ظرف قابل دسترسی‌اند. renderer مشترک و observer ردیف‌های پویا نیز در کد بررسی شدند.
- **فایل‌های باقی‌مانده:** ندارد؛ صفحات از renderer مشترک استفاده می‌کنند. این بازبینی نمونه‌ای است و تک‌تک routeها جداگانه پیمایش نشدند.
- **گام بعدی دقیق:** ندارد.
- **محدودیت/فرمان اجرا‌نشده:** صفحات Shop در این نوبت به‌علت خطای schema محلی مرور نشدند؛ این محدودیت در کار Select2 ثبت شده است.

## کار فعال: الگوی مشترک نوار فیلتر Admin

- **حوزه/owner:** `admin-panel/admin-shell`؛ markup صفحه‌ها در View همان حوزه و قرارداد دیداری در `Admin/wwwroot/css/admin-ui.css`.
- **وضعیت و درصد:** قرارداد مشترک ساخته و در صفحهٔ موجودی به‌کار گرفته شد (۷۰٪؛ گسترش مرحله‌ای به Viewها و بازبینی باقی است).
- **تغییرهای تکمیل‌شده و شاهد:** `admin-filter-bar` اندازه و فاصلهٔ ورودی‌ها، Select2ها و دکمه‌ها را یکدست می‌کند؛ `admin-filter-grid` برای گروه فیلدهای هم‌ردیف و breakpoint باریک تعریف شد. موجودی نمونهٔ سه‌ستونهٔ دسکتاپ و تک‌ستونهٔ موبایل است.
- **فایل‌های باقی‌مانده:** نوارهای فیلتر دیگر Viewهای Admin برای مهاجرت تدریجی به قرارداد مشترک، فقط اگر markup فعلی رفتار فرم را مختل نکند.
- **گام بعدی دقیق:** ساخت Admin و بررسی breakpointهای چیدمان؛ سپس استفاده از کلاس مشترک در فیلترهای پرتکرار بعدی.
- **محدودیت/فرمان اجرا‌نشده:** اتصال Chrome هنگام بارگذاری مجدد محلی قطع شد؛ بازبینی بصری مرورگر تکرار نشده است.

## کار فعال: صفحه‌بندی دیتابیسی فهرست‌های پُرحجم Admin

- **حوزه/owner:** APIهای Admin در `Admin/Controllers/Api/`، queryهای EF Core و رابط‌های جدول در View/JS ownerهای ثبت‌شده در `tools/ui-owners.json`.
- **وضعیت و درصد:** صفحه‌بندی دیتابیسی پیاده‌سازی و برای قراردادهای API/رابط پنج آزمون ایستا اضافه شد (۹۵٪؛ build و آزمون‌ها موفق).
- **تغییرهای تکمیل‌شده و شاهد:** کاتالوگ محصولات، پیش‌نویس کالا و ماتریس قیمت تنوع/پیشنهاد اکنون قبل از materialize روی SQL فیلتر و صفحه‌بندی می‌شوند. صفحهٔ حواله سفارش‌های پرداخت‌شده از سقف ثابت ۲۰۰ ردیف به صفحه‌های ۵۰تایی با total تبدیل شد و انتخاب‌ها بین صفحه‌ها می‌مانند؛ سقف ۲۰۰ مورد برای ثبت حواله حفظ شد. سفارش‌ها، مشتریان، موجودی، سندها، گردش‌ها و پیام‌ها پیش‌تر در API صفحه‌بندی داشتند.
- **فایل‌های باقی‌مانده:** بررسی تعاملی صفحه‌ها با نشست محلی و دیتابیس آزمایشی کامل؛ فهرست‌های کوچک تنظیماتی و lookupهای لازم برای فرم‌ها عمداً کامل بارگذاری می‌شوند.
- **گام بعدی دقیق:** پس از آماده‌شدن Chrome و دیتابیس آزمایشی دارای schema فروشگاه/انبار، صفحهٔ اول/بعدی و جست‌وجو را در Admin مرور کنید.
- **محدودیت/فرمان اجرا‌نشده:** `npm test` (پنج آزمون قرارداد)، build کل solution، `npm run check`، بررسی syntax سه فایل JS و `git diff --check` موفق شدند. اجرای محلی Admin با تنظیم فعلی به دیتابیس غیرمحلی اشاره می‌کند؛ برای حفظ محدودیت تست محلی، نشست کاربری/GETهای دیتابیسی اجرا نشدند. Chrome نیز در حال حاضر اجرا نیست و راه‌اندازی آن نیاز به پاسخ کاربر دارد. هیچ داده‌ای تغییر نکرد.

## کار تکمیل‌شده: سامان‌دهی منوی Admin

- **حوزه/owner:** `admin-panel/admin-shell` در `tools/ui-owners.json`.
- **وضعیت و درصد:** کامل (۱۰۰٪).
- **تغییرهای تکمیل‌شده و شاهد:** `Admin/Views/Shared/_AdminSidebar.cshtml` گروه کاربران را از عملیات و داده‌های انبار جدا کرد؛ پیوندهای سفارش، مشتری و محتوای محدود به `system.full-access` با مجوز واقعی route هماهنگ شدند؛ عنوان بخش‌های خالی پنهان است. نقشهٔ نهایی در [راهنمای Admin](../admin/README.md) ثبت شد.
- **فایل‌های باقی‌مانده:** ندارد.
- **گام بعدی دقیق:** ندارد؛ در صورت افزودن route یا مجوز، منو را با Controller و catalog مربوط تطبیق دهید.
- **محدودیت/فرمان اجرا‌نشده:** مرور بصری مرورگر در این نوبت انجام نشده است؛ کنترل‌های خودکار قرارداد UI و مستندات اجرا می‌شوند.

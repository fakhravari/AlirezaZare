# طرح‌های فروش، offer و quote

قرارداد API در `Shop/Controllers/SalesPlansController.cs` است؛ منبع runtime از `ISalesPlanSource`/`DatabaseSalesPlanSource` و repositoryهای `Data/` تأمین می‌شود. صفحهٔ محصول، کارت‌ها و checkout مصرف‌کننده‌اند. تغییرات مدیریتی را در endpointهای Admin مربوط به کاتالوگ/قیمت دنبال کنید.

## API جاری

- `GET /api/store/sales-plans`: فهرست طرح‌ها و offerها.
- `GET /api/store/sales-plans/products/{productId}`: طرح‌ها، offer، variantها و price options کالا.
- `GET /api/store/sales-plans/products/{productId}/price-history?salesPlanId=...&optionPriceVersionIds=...`: نسخه‌های قیمت برای scopeهای انتخاب‌شده.
- `POST /api/store/sales-plans/quote`: محاسبهٔ خط با انتخاب‌ها.
- `POST /api/store/sales-plans/validate-cart`: محاسبهٔ مجدد اقلام cart.

هر variant انبار فیلد `IsDefault` غیرتهی دارد. migration شمارهٔ 067 برای داده‌های موجود در هر محصول یک variant پیش‌فرض تعیین می‌کند و index یکتا از چند پیش‌فرض جلوگیری می‌کند. پنل تعریف‌های انبار همان مقدار را تغییر می‌دهد. افزودن سریع از کارت خانه variant پیش‌فرض را همراه شناسهٔ آن به quote و سبد می‌فرستد؛ اگر variant پیش‌فرض موجود نباشد، افزودن متوقف و پیام اصلاح تنظیمات نمایش داده می‌شود. محصول بدون variant هم مستقیم افزوده می‌شود. accessoryهای اجباری در افزودن سریع می‌آیند و انتخاب‌های جزئیات با ID در جداول فرزند `Account.CartItem` ذخیره می‌شوند؛ گزینهٔ قیمت نیازمند انتخاب، کاربر را به صفحهٔ محصول می‌برد.

طرح فروش مشخص می‌کند کدام offer فعال و قابل خرید است. quote سمت سرور منبع مبلغ/شرایط خرید است؛ snapshot cart فقط برای نمایش و ارسال انتخاب است. افزودن کالا از quote استفاده می‌کند؛ ذخیرهٔ سبد حساب نیز stock offer و در صورت وجود stock تنوع را دوباره می‌سنجد. پیش‌نمایش checkout با `validate-cart` هر خط را quote می‌کند و ثبت فاکتور هم ردیف‌های ذخیره‌شده را دوباره از دیتابیس می‌خواند و اعتبار، سقف تعداد و موجودی را کنترل می‌کند. طرح غیرفعال، خارج از بازه یا offer نامعتبر نباید به طرح دیگری fallback شود.

## قیمت و تاریخچه

فهرست‌های ویرایش انبوه قیمت تنوع‌ها و پیشنهادهای کالا در Admin با `page` و `pageSize` سمت دیتابیس صفحه‌بندی می‌شوند؛ `q` نیز پیش از شمارش و دریافت صفحه در query اعمال می‌شود. پاسخ هر فهرست شامل `items`، `total`، `page` و `pageSize` است. برای افزودن فیلتر، آن را در query پیش از `CountAsync` و `Skip/Take` اعمال کنید و ترتیب را با کلیدهای پایدار قطعی نگه دارید.

نسخه‌های قیمت در `Store.PriceVersion` نگهداری می‌شوند. برای هر `ScopeKey` نسخهٔ فعال آخرین قیمت جاری است و نسخه‌های قبلی با زمان UTC، مبلغ، تخفیف، دلیل/عامل تغییر و پیوند نسخهٔ قبلی باقی می‌مانند. انواع scope در `Data/Domain/Store/Entities/StorePriceVersion.cs` تعریف شده‌اند. API تاریخچه در [راهنمای محصول](product.md) تشریح شده است.

در هر ردیف سفارش، `StoreOrderItemPriceReference` شناسهٔ هر نسخهٔ قیمت اعمال‌شده را وصل می‌کند؛ با این رابطه می‌توان مبلغ پایه، variant، option و accessoryهای قیمت‌دار را برای مغایرت‌گیری بازسازی کرد. تاریخچهٔ قبل از شروع versioning با snapshot اولیه قابل بازیابی نیست.

Migration نمونهٔ `074-pricing-status-sample-data.sql` برای بررسی قیمت‌گذاری، یک گروه گزینه با دو مقدار قیمت‌دار، تنوع فعال/غیرفعال، متعلق فعال/غیرفعال، نسخهٔ قیمت جاری و سابقهٔ غیرفعال و کوپن فعال/غیرفعال اضافه می‌کند. رکوردهای آن کلیدهای `sample-status-*` و کدهای `TESTACTIVE15` و `TESTINACTIVE15` دارند و با دادهٔ نمونهٔ کاتالوگ موجود کار می‌کنند. قیمت غیرفعال در `PriceVersion` سابقه است؛ query جاری فقط نسخهٔ فعال را به‌عنوان مبلغ جاری می‌خواند.

Migration `075-sample-accessory-price-version.sql` اطمینان می‌دهد که متعلق نمونه هم برای طرح فعال نسخهٔ قیمت جاری داشته باشد؛ قیمت رابطهٔ `ProductAccessory` و نسخهٔ قیمت باید با هم برابر بمانند.

گزینهٔ خرید در schema فعلی فیلد وضعیت مستقلی ندارد. نسخهٔ غیرفعال ثبت‌شده برای مقدار نمونه صرفاً سابقهٔ قیمت است و به‌تنهایی آن مقدار را از فهرست گزینه‌های قابل انتخاب حذف نمی‌کند؛ برای آزمون نمایش/quote گزینهٔ جاری، مقدار نمونهٔ فعال را به‌کار ببرید.

## هنگام تغییر قرارداد

قیمت/موجودی را در UI دوباره محاسبه نکنید؛ quote را از API بگیرید. شناسهٔ پایدار plan، product، variant و price version را حفظ کنید. مبلغ در قرارداد جاری تومان صحیح و ارز `IRT` است؛ واحد و گردکردن را در DTO و تست قرارداد بررسی کنید.

مرجع جریان خرید: [سبد](cart.md)، مرجع schema: [پایگاه داده](../architecture/database.md)، مرجع داده‌های runtime: [منابع داده](../architecture/data-sources.md).

بررسی: plan نامعتبر/منقضی، چند offer برای یک کالا، variant/option قیمت‌دار، تغییر قیمت بین مشاهده و checkout، و نگهداری ID قیمت در order item.
